# RK3588 System Monitor 项目导读

## 项目来源与学习目标

本项目基于 Udacity 的 `CppND-System-Monitor` 教学起始仓库，原始地址：

```text
https://github.com/udacity/CppND-System-Monitor
```

上游采用 MIT 许可证。标签 `upstream-baseline` 固定未经修改的原始代码，后续提交用于记录在 Ubuntu 和 RK3588 上的逐步实现，不把上游教学框架表述为个人从零设计。

首轮学习目标是掌握 Linux 应用开发中常见的 `/proc`、`/sys`、CMake、C++对象建模、终端显示、调试和部署。RK3588 专用监控、线程采样、Unix Socket 和 GDB/strace 将分阶段加入。

## 原始架构

```text
/proc、/etc
    ↓
LinuxParser：读取并解析Linux伪文件系统
    ↓
System / Processor / Process：组织系统、CPU和进程数据
    ↓
NCursesDisplay：在SSH终端持续刷新界面
```

## 第一阶段代码阅读顺序

1. `src/main.cpp`：程序入口，创建 `System` 并启动显示。
2. `src/ncurses_display.cpp`：观察界面每秒如何读取模型数据。
3. `src/system.cpp`：理解系统模型如何调用解析器。
4. `src/linux_parser.cpp`：定位 `/proc` 与 `/etc` 的实际读取逻辑。
5. `src/process.cpp` 与 `src/processor.cpp`：理解单进程和CPU利用率的封装。

## 当前真实状态

原仓库是教学骨架，不是完成品。首次审计共发现约 460 行 C++，多个核心函数仍返回 `0`、空字符串或空容器。因此第一阶段的“编译通过”只证明构建链路成立，不代表监控数据已经正确。

首次使用现代 ncurses 编译时，源码直接访问 `WINDOW->_maxx` 和 `WINDOW->_maxy`，但 `WINDOW` 是库的内部结构，当前头文件只暴露不完整类型。第一处迁移修复改为公开接口 `getmaxx()` 和 `getmaxy()`，同时避免窄终端下产生负长度。

## 现阶段不做

- 不修改内核、设备树或系统镜像。
- 不增加摄像头、RKNN、Qt或网页前端。
- 不把当前结果描述成Linux驱动项目。
- 不一次性补完所有TODO；每完成一个小闭环再提交和讲解。
